# 架构

```
官方营养表（整份）──┐
配方（配料×份数）───┼─► library：带先验的非负加权最小二乘 ─► 配料营养（含不确定度、可辨识度）
美国官网配料先验 ───┘                                     └─► 删除诊断：定位写错的配方

门店菜单 + 餐品详情 ─► catalog：单品 / 套餐各组可选项 × 吃法（整份、下单去配料、到手只吃馅）─► 选项
                                                                            │
用户约束（热量上限、蛋白下限、碳水、预算、训练部位）─────────────────────────► solver：分支定界
                                                                            │
                                                         pricing：算价接口核价 ◄─┘
                                                                            │
                                                         render：普通版 / Gyᗰ 训练计划版
```

## 模块

| 模块 | 职责 |
|---|---|
| `mcp.py` | Streamable HTTP 客户端：直连优先、重试、节流；业务码非 200 抛 `McdBusinessError` |
| `nutrition.py` | 解析营养表紧凑文本，菜单名与营养表名归一 |
| `linalg.py` | Cholesky、对称正定求逆、Lawson–Hanson 非负最小二乘 |
| `library.py` | 配料库求解、后验标准差、可辨识度、残差与删除诊断 |
| `catalog.py` | 菜单与详情解析、差价解析、吃法生成、套餐选项支配剪枝、实时拉取与缓存 |
| `solver.py` | 支配过滤、分支定界、最小性约束、训练部位标签约束、前 k 名 |
| `pricing.py` | 算价参数构造（特制参数全量传）、核价 |
| `render.py` | 普通版和训练计划版文案、合并只差零卡饮料的方案 |
| `cli.py` | `library` 与 `plan` 两个子命令 |

## 关键设计

- **营养以官方整份为锚点。** 吃法的营养 = 官方整份 − 去掉的配料，整份吃法与官方完全一致；配料库只负责「差额」。
- **两类定制分开。** 「下单去配料」写进 modification，价格不变（实测）；「到手只吃馅」接口做不到，作为吃法建议，单独给出留存部分的营养。
- **方案必须最小。** 去掉任何一项仍满足蛋白目标的方案视为多余，不进入结果。
- **价格以接口为准。** 预测价格只用于排序，最终逐个用 calculate-price 核对。
